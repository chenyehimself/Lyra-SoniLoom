# v0.4 — Local short-recording authoring

Approved after recommending a clean short-recording workflow on 2026-10-02. No uploads, cloud account/storage integration, external sample acquisition or semantic source separation. The prior Google Drive upload authorization is not used in this iteration.

## Implementation sequence
1. Freeze legacy sample and v0.3 spatial render hashes. Add schema 3 / engine 0.4 with optional paired sourceIn/sourceOut times in original recording seconds. Preserve schema 1 and 2 audio unchanged. Explicit, undoable sample-editor opt-in for old projects preserves previous playback until a selection is applied.
2. Add non-destructive waveform selection, exact in/out values, previewed effective playback duration and a deliberate fit-clip action. Existing level, fades (attack/release), speed and reverse apply to the selected interval. Speed changes pitch and duration together. Timeline position remains independent of source coordinates. Every completed selection is one revision.
3. Compute local measurements (source duration, rate, channels, absolute peak, peak location and an amplitude threshold onset estimate). Send only bounded measurement metadata and parameters to the existing GPT planner. Metadata is not semantic listening; no raw audio leaves the local app.
4. Extend scoped AI proposals to the paired selection fields, keeping asset identity/bytes and protected layers unchanged. Retain manual/AI validation, stale guards, undo and original-content hashes.
5. Verify imports, selections, boundary interpolation, reverse/rate/fade interaction, no out-of-selection leakage, locks, invalid atomic changes, roundtrips and legacy hashes. Exercise local browser waveform/numeric changes, undo, rendered previews and actual file downloads. Paid verification remains inside the original cumulative USD 5 guard; no retries to bypass it.

## Components and tradeoffs
project/assets/engine define the versioned source window; a small sample helper holds bounds/measurement logic; AI contract/server expose validated metadata; app/inspector show original waveform and editable selection. New project format requires v0.4; old projects are not silently migrated. Waveform drag provides coarse selection, numerical editing provides precision. Long-recording search, pitch-independent stretch, automatic cleanup and destructive edits are excluded.

## Acceptance and stop
Original WAV bytes/hash survive every edit. Three sequential selected-layer edits preserve untouched content and save/reopen to identical rendered WAV. New source-window behavior is explicit and legacy hashes remain fixed. Test evidence, file evidence, browser evidence, provider evidence and human listening are reported separately. No claim of realistic recorded material is made from a synthetic verification fixture. Stop when this clean-short-source editing loop is ready for the owner's real recording and listening; do not acquire or fabricate a supposedly real sample. No Git/branch/PR/deploy actions, dependencies or other Lyra changes.
