# Lyra SoniLoom v0.2 — Acceptance criteria and execution plan

Approved 2026-10-02: real AI integration, SoundRack-inspired UI, autonomous implementation and verification, live API test budget at most USD 5. Reuse the dedicated key in the approved `.env.local`. No additional credential provisioning.

## Acceptance criteria

1. A real OpenAI response proposes a multi-layer sound from a Chinese or English description. Owned DSP creates all audio. Provider identity and failure are explicit; no canned response masquerades as AI.
2. At least three sequential conversational edits use the same current project and stable layer IDs. Current project state, including manual changes and undo, overrides conversational memory.
3. Every proposal lists its exact changes and requires Apply. The selected scope (whole sound or selected layer) is enforced in code. Locked layers cannot be changed, removed or unlocked by AI. Stale proposals cannot apply after any project revision/replacement. Invalid proposals preserve the last valid project atomically.
4. One Apply equals one undoable edit. Unchanged layer settings, original imported WAV bytes and isolated PCM are preserved. Save/reopen and WAV export continue using the existing engine.
5. UI adopts SoundRack's compact current-sound header, readable conversation, composer and distinct workspace/detail hierarchy. Replace competing marketing headings with functional titles; retain accessible editing controls. Check desktop and narrow layout, plus loading, errors, proposals and history.
6. Credentials remain server-only. AI receives bounded text, parameters and asset metadata, never WAV bytes. Limit requests, output tokens, concurrency and durable test spend; no automatic retries. Stop before a call that would exceed the USD 5 budget, counting uncertain requests conservatively.
7. Tests cover valid and rejected proposals, scope, locks, stale state, atomicity, history, asset preservation, provider failure and budget persistence. Real provider evidence is recorded separately from test doubles. Browser interactions and persisted audio/project evidence are recorded separately from human listening.

## Decisions and tradeoffs

- Apply confirmation adds a click but gives a precise, reviewable edit boundary. Scope defaults to whole sound; selecting a layer can explicitly restrict it.
- The existing fixed per-layer DSP chain remains. Arbitrary graph routing and new synthesis algorithms are not required for this version.
- Conversation history is session-local; the sound project remains portable. This avoids changing the persistent project schema for a chat UI.
- Local account-wide billing cannot be capped by this app. The USD 5 guard covers only this prototype's own recorded API calls; it does not claim to limit other project/account clients.
- Model availability is checked with an actual bounded call. No automatic fallback to another model or hidden repeated attempts.
